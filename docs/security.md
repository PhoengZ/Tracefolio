# Security boundaries

Private registries, environment bindings, state, proposals, and exports belong outside the checkout and source roots. The runtime restricts state to the current user: mode 0700/0600 on POSIX and a protected current-user FullControl ACL on Windows. Setup fails if it cannot establish this boundary. Existing insecure descendant files, backups, cloud sync, administrators, and a compromised same-user process are outside that guarantee. Exports are atomic and must stay inside the private state's dedicated `exports/` subtree; internal state namespaces cannot be export targets. Arbitrary folder ACLs are never modified for export.

Application code contains no personal source paths, endpoints, tokens, or real work. The synthetic examples use environment references. Local source bindings must be absolute non-home, non-drive roots. Relative scopes cannot contain parent traversal or absolute paths. Symlink/junction escapes are rejected at resolution. Filesystem checks reduce accidental scope escape; they are not race-proof against a hostile process changing the same filesystem during IO.

Collectors are read-only. A local Git binding must resolve to the repository top-level directory; scope a subdirectory with include globs. Nested Git directory bindings are rejected before content acquisition. Local Git disables external diff, textconv, pager, signature execution, and filesystem monitor integration; it does not run hooks or change refs/index/worktree. Only committed Git data is read. Non-Git directories use bounded text snapshots, including deletion detection and a resumable cross-file verification pass; these are observations over time, not atomic filesystem snapshots. Verification can require additional collection runs even after the initial file scan. Notebook parsing retains code/Markdown source and cell provenance, strips outputs/metadata/attachments, and never executes cells. Large or unavailable content keeps coverage partial.

Mandatory exclusions remove hidden credential files, dependencies, caches, build outputs, and binary content. Explicit include/exclude scopes further narrow collection. The default public GitHub transport is anonymous HTTPS to the fixed API host, with redirects, proxy inheritance, auth headers, and credential helpers disabled. After an anonymous rate limit, the external harness may select the [plugin STDIO bridge](github-plugin-workflow.md) only with user authorization. This transport sends validated fixed-host GET requests and accepts bounded matching UTF-8 JSON replies from the harness; it does not invoke MCP, obtain credentials or cache raw responses on disk. The trusted harness must supply the exact unmodified tool response, keep raw bodies in memory and avoid PTY echo. The connected plugin has its own account permissions, but the provider still rechecks public visibility before further ref/content reads. Private/404/unavailable responses retain gaps and never trigger a private/local fallback. Public visibility is not ownership or permission to disclose derived private context. Opt-in bridge request events contain repository URLs for machine routing; treat that pipe as private and exclude it from public logs.

Raw content is redacted **before evidence persistence**, including messages, removed/added diff lines, paths, and context. Known selected bindings, owner emails, extra private redaction strings, common credential patterns, URLs, absolute POSIX/drive/UNC paths, emails, and private IPs are sanitized. Generic path detection can also redact code strings such as root-relative API routes; division operators and relative glob separators are preserved where distinguishable. This is heuristic and cannot detect every secret or confidential fact. Add organization-specific literals using the private redaction binding. The current algorithm is `redaction-v2`; changing the algorithm or explicit redaction policy requires a new state root. Old state remains private and is not automatically purged. A new model provider is not implicitly authorized. Inspect packets before sharing beyond your approved harness.

Sources are untrusted data. No embedded instruction can authorize another directory, endpoint, command, notebook execution, or integration. The external harness must follow AGENTS.md and the scoped context procedure. No untrusted schema URI is dereferenced: validation uses committed local Draft 2020-12 schemas. Validation establishes shape and reference consistency, not factual truth, good English, ownership, or absence of confidential information.

Project writes use an exclusive project lock, immutable files, and atomic CURRENT replacement. CURRENT points at a control revision that selects both the analysis ledger and semantic generation. Failed publication leaves the prior pointer valid; unused immutable files can remain after interruption. A stale lock is not deleted automatically: confirm no writer is running before manually removing that one private lock directory. There is no concurrent multi-user service, retention manager, or encrypted storage layer in Phase 1. Use operating-system disk encryption/backups as appropriate to your environment.

No source execution, Gmail connection, email draft/send, job application, resume/PDF generation, scheduling, bucket upload, or public export is implemented.

Repository-local state is an explicit exception only for `.tracefolio-local/state` under a privately bound Git top level. Git ignore and untracked checks, link rejection, owner-only permissions and source/registry overlap checks still apply. Migration rejects links throughout the source tree, verifies durable hashes/references, and blocks writers during copy and binding activation. Old-root retirement blocks stale writers. Private state is excluded from acquisition and package artifacts. Exports stay within the active state exports namespace.
